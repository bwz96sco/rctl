# v0.6.5 deployment — 2026-10-12

Released source: `e2cca134d1d075d568df956ad7b1bf9b6f04d834`. With 0.6.4, a task one
session began was selected automatically in every session of the project. After
comparing how Trellis tracks several tasks, the user authorized
[per-session task selection](DEVELOPMENT.md#per-session-task-selection-10-october-2026)
and then this release ("执行下更新"). `begin`, `reopen` and the new `task use TASK`
record the calling Claude Code or Codex session's task in a self-ignored
`.rctl/sessions/` pointer; reminders use `RCTL_TASK_PATH`, then that pointer, then
the only active task, and `close`/`cancel` clear pointers to the task. Hook receipts
gain the `session` selection kind. The packaged research-task `SKILL.md` and
`references/workspace.md` and the generated host READMEs describe the rule. Schemas,
task records and the lifecycle are unchanged. The release also packages `937d8a0`, a
research-rapid-test skill change committed separately.

## Limitations

The OR probe ran non-interactively and only for Claude Code; Codex session delivery
rests on the pre-release disposable-project probe on codex-cli 0.162.1. Sessions
started before installation keep the 0.6.4 skill text they loaded and do not know
`task use`, though their reminders now come from 0.6.5. A session without a pointer
still receives the only active task automatically. Pointers from sessions that end
without `close` remain until their task ends. A host launched from another host's
shell sees both session variables and writes no pointer. Interactive sessions and
Claude Code `/clear` were not observed.
