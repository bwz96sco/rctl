# Note workflows

## Literature and synthesis

Start from `literature-index.md`, then the topic's register and specific paper notes.
Use paper-discovery for the corpus, research-literature for full-paper evidence, and
research-synthesis for a cross-paper answer. Verify citations and cite note anchors.

## Managed research work

Select the rctl task explicitly. Read its contract and status before dependent work, then
follow the relevant experiment, computation, theory, figure, slide, or writing skill.
Keep domain artifacts in their existing note locations and reference them from task criteria
and results. Use task-relative evidence paths in the contract, including paths into the vault.
Keep raw runner outputs in project storage. A domain validator checks only its stated scope;
it does not close the rctl task or authenticate an evidence-based review.

## Existing assets

Read applicable intake notes before starting new work. Reuse established evidence when its
provenance and comparison contract fit; record gaps that change the next action. Preserve
historical artifacts. Live task migration is an explicit operation, separate from init.

## Progress summaries

Use `rctl status TASK` for current phase and acceptance. Read notes and runner artifacts for
scientific findings. Link the relevant tasks and summarize established findings, unresolved
questions, and a concrete next action; avoid a second mutable status board in the vault.
